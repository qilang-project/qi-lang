# Qi 工具链

版本 2026.07.12-1。安装：

```bash
brew tap qilang-project/qi https://github.com/qilang-project/homebrew-qi
brew install qi
```

安装布局：`/usr/local/bin/qi`（编译器）+ `/usr/local/lib/qi/`（`libqi_runtime.a` 运行时归档、`libqi_gui.a`、依赖 dylib）——解压即用，编译产物链接时自动从 `lib/qi/` 取运行时。也有 macOS .pkg / Windows .msi / tar.gz 安装包（qi-installer）。

## CLI 命令（双语，全部有中文别名）

```
qi run 程序.qi          运行     编译并运行
qi compile 程序.qi -o 出 编译     编译为可执行文件
qi check 程序.qi        检查     只查语法，不产出
qi check-run 程序.qi    检查运行  先查语法再运行
qi format 文件.qi       格式化    ⚠️ 未实现的桩（只打印文件名不动文件），用 qifmt
qi debug 程序.qi        调试     调试模式编译运行
qi info                信息     编译器信息
qi test [路径]          测试     发现并运行 *_测.qi
qi get [包地址]         拉取     拉取远程依赖（见 包管理.md）
```

常用全局选项：

```
-O none|basic|standard|maximum    优化级别，映射 O0-O3（默认 O1/basic 档）
-o <路径>                          输出文件
-t/--target linux|windows|mac-os|wasm   目标平台
--arch x86_64|aarch64             交叉编译架构（默认 x86_64）
--release-runtime                 交叉链接用 release 运行时归档（产物更小）
-d/--debug-symbols  --verbose  --warnings-as-errors
```

优化效果：计算密集场景与 Go 同梯队（fib(40) 实测反超 Go 约 15%）。

## qi test

- 发现规则：递归找文件名以 `_测` 结尾的 `.qi`（跳过 `qi_packages`/`target`/隐藏目录），逐个编译运行，汇总 `测试套件: X/Y 通过`，有失败退出码 1。
- `-f/--filter 关键字` 过滤用例、`-v/--verbose` 详细输出（经 `QI_TEST_FILTER`/`QI_TEST_VERBOSE` 环境变量传给测试进程）。
- 测试文件就是普通可执行程序（`包 主程序;` + `函数 入口()`），断言用 `标准库.测试`（见标准库参考），或第三方 qi-test 框架（`运行用例`/`摘要并退出`/桩与 spy）。

实测样例：

```qi
// 计算_测.qi
包 主程序;

导入 标准库.测试;

函数 入口() {
    测试.断言相等_整数(1 + 1, 2, "一加一等于二");
    测试.断言真(1, "真值断言");
}
```

```bash
$ qi test .
▶ 计算_测
  ✓ 套件通过
测试套件: 1/1 通过
```

## qifmt（格式化器）

独立二进制（qi-tools 产物）。**只动空白**：重排行首缩进（按 `{}`/`【】` 深度）、去行尾空白、折叠连续空行；**不拆行、不合并行、不动注释**，输出幂等。

```bash
qifmt 文件.qi          # 默认就地写回
qifmt --check 文件.qi   # 只检查，需格式化则退出码 1（CI 用）
qifmt --diff 文件.qi    # 打印差异
qifmt -r 目录/          # 递归目录
```

`qi format` 子命令是未实现的桩，别用。

## 交叉编译（macOS → Linux）

用 zig 链接（需 `zig` 在 PATH，`brew install zig`），产出 Linux ELF，零 Docker：

```bash
qi --target linux --arch x86_64 --release-runtime compile 程序.qi -o 程序_linux
qi --target linux --arch aarch64 --release-runtime compile 程序.qi -o 程序_arm
```

实测产物：`ELF 64-bit LSB executable, x86-64 … for GNU/Linux`（glibc 2.34 目标，`zig cc -target x86_64-linux-gnu.2.34`）。

运行时归档定位顺序：

1. 环境变量 `QI_RUNTIME_LIB_LINUX` 直接指向 `libqi_runtime.a`
2. 开发布局 `qi-runtime/target/<arch>-unknown-linux-gnu/{release|debug}/libqi_runtime.a`（`--release-runtime` 优先 release）

归档缺失或版本过旧（链接报 `undefined symbol: qi_obj_dec` 等 ARC 符号）时，在 qi-runtime/ 重建：

```bash
cargo zigbuild --target x86_64-unknown-linux-gnu --release
```

宿主==目标（如 macOS 上出 macOS 产物）走原生 clang，无需 zig。

## 内存管理：ARC（自动引用计数）

**默认开启**，字符串、结构体、数组、闭包环境四类对象自动 retain/release 回收（跨线程计数用原子操作；字符串字面量不朽、retain/release 为 no-op）。写代码无需手动释放这四类；**句柄式资源**（JSON/列表/哈希表/服务器/子进程句柄）仍要手动 `删除`/`释放表`/`关闭` 等。

环境变量（运行**编译出的程序**时设置，非编译期）：

```bash
QI_ARC=0 ./程序          # 关闭 ARC，退回泄漏模式（调试用；QI_ARC=false 同义）
QI_RC_REPORT=1 ./程序    # 退出时打印活跃对象计数，检测泄漏
# 输出形如：[qi-rc] 活跃对象=1 活跃字符串=0 活跃闭包=0
```

**循环引用不回收**（纯引用计数无环检测，同 Swift）——结构体互相持有会泄漏，长驻进程注意打破环或用句柄间接引用。

## 调试相关环境变量汇总

| 变量 | 作用 |
|---|---|
| `QI_ARC=0` | 关 ARC（泄漏模式） |
| `QI_RC_REPORT=1` | 退出时打印活跃对象计数 |
| `QI_CORO=0` | 关真协程，退 eager future（默认开，2026.07.12 起） |
| `QI_CORO_WORKERS=N` | 协程执行器 worker 数（默认 = CPU 逻辑核数） |
| `QI_ASYNC_WORKERS=N` | goroutine 运行时 worker 线程数 |
| `QI_LLM_RECORD/REPLAY/CACHE=1` + `QI_LLM_TAPE=文件` | LLM 磁带录制/回放/缓存（见 大模型.md） |
| `QI_PACKAGES_PATH` | 第三方包搜索根（见包管理） |
| `QI_RUNTIME_LIB` / `QI_RUNTIME_LIB_LINUX` | 指定运行时归档 |
| `QI_TEST_FILTER` / `QI_TEST_VERBOSE` | qi test 过滤/详细 |
| `QI_HOME` | 覆盖 `~/.qi`（包缓存根） |

## 观测性与 FFI(2026.07.05 起)

**ARC 循环引用检测**(编译期):默认警告可能的引用环(纯 RC 无环收集器,环=泄漏),`QI_LINT=0` 关、`QI_LINT=strict` 升编译错误(CI 卡关)。破环:暂无 weak 语法,用整数 id 间接引用。

**性能剖析器**:`QI_PROF=1 qi run 程序.qi` 退出打函数级 CPU 报告(总耗时/调用次数/占比,wall-inclusive);关闭时零注入零开销。长驻服务用 `qi compile` 出产物直接跑(qi run 吞信号退出的 stderr),Ctrl-C 收尾打报告。

**外部 C 函数**:`外部 "库名" { 函数 名(参数:类型): 返回; }` 声明 + 裸调用,链接期 -l库名。C ABI:整数↔long、浮点数↔double、布尔↔int、字符串↔const char*。v1 参数支持 整数/浮点/布尔/字符串,返回支持 整数/浮点/布尔/空(char* 返回暂不支持)。

**qi-bindgen**:`qi-bindgen 头.h --库 <lib> [--前缀 SSL_] [-o out.qi]` 用 libclang 解析 C 头自动生成 外部 声明;不可映射类型跳过并注释。大库必须 --前缀 过滤。

## 反向 FFI / 诊断 / 信创(2026.07.09 起)

**导出为 C 库**(双向 FFI): `导出 [C名] 函数 名(参数): 返回 { }` 声明 C ABI 导出; `qi compile --库 静态|动态 x.qi -o lib.a|lib.dylib --头 x.h` 出库+C 头。别人的 C/Rust/Go `#include` 后即可调用你用中文写的函数(qi_add(3,4)=7)。字符串返回 strdup 给 C(C free)。mac 静态库需带 -framework, 动态库免。

**qi doctor 一体化诊断**: `qi doctor 程序.qi [--测CPU --查漏 --json]`(中文别名 诊断)聚合静态环检测+profiler+RC, 出联动报告(内存拓扑环 + CPU 热点 + 活跃对象, 关键是"泄漏←→环"联动提示)。

**信创龙芯交叉编译**: `qi --target linux --arch loongarch64 --release-runtime compile 程序.qi -o 程序`(别名 loong64)。前置: `rustup target add loongarch64-unknown-linux-gnu` + `cd qi-runtime && cargo zigbuild --release --target loongarch64-unknown-linux-gnu`。产物是标准 LoongArch ELF64, 可拷统信 UOS/麒麟龙芯版(glibc≥2.36)。鲲鹏/飞腾用 --arch aarch64、兆芯/海光用 --arch x86_64(本就支持)。
