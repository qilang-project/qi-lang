# Qi 包管理与项目组织

自带包管理：`qi.toml` 清单 + `qi get` 拉取 + `qi.lock` 锁定。编译期**绝不联网**（远程依赖只读本地缓存，缺失时报「请先运行 qi get」）。

## qi.toml 清单

键名中英皆可（`[包]`/`[package]`、`名称`/`name`…），中文键无需加引号（编译器自动规范化）：

```toml
[包]
名称 = "演示应用"       # 包名 = 导入时的首段名
版本 = "0.1.0"
入口 = "主程序.qi"      # 入口文件

[源码]
目录 = ["."]            # 源码目录列表，相对清单所在目录；缺省 ["."]

[依赖]
工具 = "../工具库"                                   # ① 本地路径
Web = "github.com/liliang-cn/qi-web@v1.0"            # ② 远程裸字符串 host/owner/repo[@ref]
Harness = { git = "https://github.com/x/y", 引用 = "v2.1", 子目录 = "harness" }  # ③ 详细表
```

- 依赖键 = 导入用的别名（`导入 工具::{...}`、`导入 Web::{...}`）。
- 详细表键：`git`(别名 仓库)、`引用`(别名 ref/tag/branch，可为 tag/分支/commit)、`子目录`(monorepo 用)、`路径`(本地，与 git 互斥)。
- 判定规则：首段像域名（`xx.tld/...`）→ 远程；`./` `../` 或普通路径 → 本地。
- `[元数据]` 段（描述/作者）可写，编译器忽略，纯文档用途。

实测的本地路径依赖工程（可直接照抄）：

```
工具库/
├── qi.toml            # [包] 名称 = "工具"，入口 = "工具.qi"
└── 工具.qi            # 包 工具;  公开 函数 平方(x: 整数): 整数 { ... }
应用/
├── qi.toml            # [依赖] 工具 = "../工具库"
└── 主程序.qi
```

```qi
// 应用/主程序.qi
包 主程序;

导入 工具::{平方, 问好};

函数 入口() {
    打印行(问好("世界"));
    打印行(平方(9));
}
```

`qi run 应用/主程序.qi` 直接可跑（qi 从源文件向上找最近的 qi.toml）。

## qi get（拉取）

```bash
qi get                                    # 拉取当前项目 qi.toml 全部远程依赖，写 qi.lock
qi get github.com/x/y@v1.0                # 拉取并把依赖写进 qi.toml（保守逐行插入，不动注释）
qi get github.com/x/y@v1.0 --名 别名       # 指定依赖别名
```

- 缓存位置（Go 风格）：`~/.qi/packages/src/<host>/<owner>/<repo>@<ref>/`（`QI_HOME` 可改根）。拉取幂等：目录已存在即跳过。
- tag/branch 浅克隆（`git clone --depth 1 --branch`）；commit hash 则完整克隆后 detach。克隆完删 `.git` 省空间，写 `.qi_source.toml` 记录 url/ref/commit。需要系统 `git`。
- `qi.lock`：锁 `格式版本`/`根包`/每个包的 名称/版本/来源(`git+url@ref` 或 path/workspace)/提交(commit)。提交 lock 文件可复现构建。

## 导入解析顺序

`导入 X` 或 `导入 X.子模块` 的首段 X 依次尝试：

1. 显式相对路径（`./` `../` 开头）：按路径找 `X.qi` 或 `X/X.qi`
2. 首段 == 本包名 → 按 `[源码].目录` 解析包内子模块
3. 首段 == qi.toml `[依赖]` 里的别名 → 本地路径直取 / 远程从缓存取
4. 当前目录 `X.qi`，再 `X/X.qi`
5. 第三方包目录链（找 `X/qi.toml` 或 `X/X.qi`）：
   `QI_PACKAGES_PATH` → `cwd/qi_packages` → `~/.qi/packages` → `/usr/local/lib/qi/packages` → 源文件各级祖先目录的 `qi_packages/`

`导入 标准库.*` 是编译器内建，不走文件解析。

## 多文件项目组织

`qi run/compile` 只接受**入口文件**（不是目录）。同目录多文件有两条路：

**① 同包自动发现（零导入）**——同目录下满足「同包名 + 无 `函数 入口` + 无任何 `导入`」的 `.qi` 文件自动并入编译：

```qi
// 入口.qi
包 主程序;
函数 入口() { 打印行(三倍(5)); }   // 直接调用，无需导入

// 工具函数.qi —— 同目录，自动被发现
包 主程序;
函数 三倍(x: 整数): 整数 { 返回 x * 3; }
```

注意：辅助文件一旦自己写了 `导入`，就不再被自动发现，必须走 ②。

**② 显式相对导入**：

```qi
// 主程序.qi
包 主程序;
导入 ./辅助;
函数 入口() { 打印行(辅助双倍(21)); }

// 辅助.qi
包 主程序;
公开 函数 辅助双倍(x: 整数): 整数 { 返回 x * 2; }
```

**库包**：`包 自己的包名;`（不是 主程序）、不写 `函数 入口`、对外函数加 `公开`。使用方经 qi.toml 依赖 + `导入 包名::{函数}` 调用。库包里的 `入口` 不会与使用方冲突（只有入口模块发出 `@main`）。

规模化组织范式（qi-todo-web 实例）：入口 `主程序.qi` 极薄，业务拆进子包目录（`待办应用/状态.qi`、`待办应用/路由.qi`…），`导入 待办应用.状态::{设连接, ...}` 点路径 + destructure 组合。
